# MTBox 概要设计（v0.1 草案）

> 定位：在**无海外网络**的 NAS 上，用最小复杂度跑通
> **MT 订阅 → 搜索选种 → qB 下载 → 整理入库 → 保种清理** 这一条主链路。
>
> 状态：**关键决策已确认**（2026-10-26），详细设计见 [详细设计.md](详细设计.md)。
> 工作名：MTBox（可改）。
>
> **实现状态（2026-10-31，对照 0.6.3 源码校订）**：M0–M3 主体与豆瓣榜单已实现；
> 本文 §13 的 `/api/*` 内部 API、§16 第 4 项网页登录提醒、§17 的 M4 打磨项
> **尚未实现**。实现现状见 [架构说明](architecture.md)；设计冲突时以代码与使用文档为准。

---

## 0. 已确认决策

| 项 | 决策 |
|---|---|
| 部署 | **极空间 NAS + Docker**（单容器） |
| 下载器 | **qBittorrent**（Web API） |
| 媒体服务器 | **不使用 Jellyfin/Emby/Kodi**；由极空间「极影视」自动刮削 |
| 自动化边界 | **先人工确认，再逐步放开**：候选池 → 人工一键下载 → 按订阅开自动 |

由此产生的两个调整：

1. **默认不生成 NFO**（极影视自带刮削）；NFO 只作为"识别失败时的兜底开关"。
2. 候选审核页是**核心功能**而非附属功能：每条候选必须能看到得分与淘汰理由；
   默认每个订阅展示**补齐已播集数所需的最优种子组合**（完整覆盖全部已播缺口，
   一条不够时多条；无法确认覆盖范围的“合集”只作兜底），需要时再展开全部，
   避免把匹配结果全部堆给用户；支持按订阅筛选并批量清理匹配噪音（只删候选
   记录，不影响已下载任务）。

## 1. 背景与已确认的两个痛点

| # | 痛点 | 本设计的回答 |
|---|---|---|
| 1 | 需要认证才能订阅/下载 | 只使用 MT 官方 **API Access Token（`x-api-key`）**，无 Cookie、无模拟登录、无会话保活。见 §8 |
| 2 | MoviePilot 臃肿，且依赖 TMDB 等海外库，NAS 无代理时不可用 | 全链路**不依赖任何海外服务**：元数据取自 MT 自身字段 + 手工订阅字段 +（可选）豆瓣；媒体服务器用我们生成的 NFO 识别，不做联网刮削。见 §11 |

> 说明：第 1 条我理解为「**站点**需要认证」。若你的意思还包括「**本系统**需要登录认证」，也已纳入设计（管理端单用户密码 + Session），见 §16。

## 2. 目标与非目标

### 2.1 目标（即可验收的口径）

1. 新增一部电影 / 一部剧的订阅后，系统能在设定周期内自动在 MT 找到符合偏好的种子；**默认生成候选待确认**，开启自动后才直接推送 qBittorrent。
2. 同一集**不会重复下载**；能感知已下载进度，持续追新。
3. 下载完成后，自动以硬链接方式整理进极影视扫描目录，命名可被极影视正确识别，**原文件不动、继续做种**。
4. 对 MT 的 API 调用严格受限速与预算约束，不触发风控；账号分享率过低时自动刹车。
5. 全流程可在**断外网**的 NAS 上运行；除 MT 与（可选）豆瓣外无任何外部依赖。
6. 单容器、SQLite、一条命令部署；资源占用可控（常驻内存 < 300MB）。
7. 可在站内浏览豆瓣公开榜单（剧集/电影/综艺：近期热门、最新上线、高分优先，
   可按年份与类别筛选，每页可选 20/50/100 条，显示总条数并支持页码跳转），
   点「订阅」自动预填标题、年份与豆瓣 ID；榜单仅用于发现与预填，不参与匹配。

### 2.2 非目标（明确不做，避免重新长成 MoviePilot）

- 多站点、多下载器插件体系（只留适配器接口，v1 只实现 MT + qB）。
- TMDB / TVDB / 豆瓣自动刮削全家桶、演职员、海报墙。
- 自动洗版（找到更好版本就替换）、自动字幕下载、字幕翻译。
- 多用户、权限体系、APP、精美前端框架 / 前端构建链。
- 智能推荐、榜单、签到、刷流、辅种。
- 站点登录保活（站点明确第三方无法代替网页登录，只做到期提醒）。

## 3. 核心设计原则

1. **单一主链路，不做平台。** 每个能力只实现一条最短路径。
2. **认证即凭证。** 只持有 API Token，不维护 Cookie 会话，不存在"过期要手动更新"的状态。
3. **宁可不抓，不可抓错。** 豆瓣/IMDb ID 强校验优先；无 ID 时要求标题相似度门槛；阈值不达标只进"待人工确认"，不自动下载。
4. **不碰下载文件。** 整理只做硬链接，下载目录内的文件永远由 qB 管理，保种不受影响。
5. **默认保守。** 首次运行 dry-run（只搜不抓），自动化默认人工确认；免费种优先；调用有全局预算；分享率有护栏。
6. **对外零依赖。** 前端不引 CDN，元数据不引海外 API，通知不用 Telegram（国内不可达）。

## 4. 与 MoviePilot 的差异

| 维度 | MoviePilot | MTBox |
|---|---|---|
| 站点 | 数十个，插件化 | 仅 MT（接口预留） |
| 认证 | 站点 Cookie / API Key 混合 | 仅 `x-api-key`，凭证不过期 |
| 元数据 | TMDB 为主，需外网 | MT 自带 douban/imdb 字段 + 手工字段，可选豆瓣 |
| 运行形态 | 较重，模块多 | 单进程 + SQLite |
| 功能面 | 订阅、洗版、字幕、整理、插件市场… | 只保留订阅→下载→整理→保种 |
| 媒体服务器 | 依赖联网刮削 | 交给极空间极影视；本项目只保证命名与目录 |

## 5. 总体架构

```
                 ┌──────────────────────── NAS / Docker ─────────────────────────┐
                 │                                                                │
 浏览器 ──HTTP──►│  Web UI (FastAPI + Jinja2, 服务端渲染)                          │
 (局域网)        │      │                                                          │
                 │      ▼                                                          │
                 │  ┌──────────────────── Core Services ────────────────────┐     │
                 │  │ Scheduler │ Subscriptions │ Matcher │ Organizer │ Seeding│     │
                 │  └────┬───────────────┬─────────────┬──────────┬─────────┘     │
                 │       │               │             │          │               │
                 │   SQLite(WAL)   MTeamClient    QBClient   FileOps(硬链接)       │
                 │                      │             │          │               │
                 └──────────────────────┼─────────────┼──────────┼───────────────┘
                                        │             │          │
                             api.m-team.cc       qBittorrent   /media
                             (x-api-key)         (Web API)     (Jellyfin/Emby)
```

单进程：FastAPI 同时提供页面与 API，APScheduler 在进程内跑定时任务，SQLite 用 WAL 模式。无 Redis、无消息队列、无独立 worker。

## 6. 模块职责

| 模块 | 职责 | 关键约束 |
|---|---|---|
| `clients/mteam.py` | MT API 封装：search / genDlToken / .torrent 下载 / member profile | 统一 UA、限速、错误分类 |
| `clients/qbittorrent.py` | qB Web API：add / info / delete / tags | 不阻塞主线程，超时 10s |
| `clients/bencode.py` | 解析 .torrent（文件列表、大小、piece） | 纯函数，可单测 |
| `clients/release_name.py` | 从标题/文件名解析季、集、分辨率、编码、中字、合集 | 纯函数，可单测，规则可配置 |
| `services/subscriptions.py` | 订阅 CRUD、到期判定、总集数/进度维护 | 状态机简单可查 |
| `services/episodes.py` | 从 PT 描述识别总集数与最新集 | 纯函数、同剧同季校验 |
| `services/search.py` | 组织关键词、调用 MT、全局限速与预算 | 所有搜索必须走这里 |
| `services/matcher.py` | 硬过滤 + 打分 + 去重 | 每个候选保留"为什么入选/淘汰" |
| `services/downloader.py` | 取 .torrent → 上传 qB → 记录 hash | 失败可重试、幂等 |
| `services/organizer.py` | 文件选择、命名、硬链接、NFO（兜底，默认关） | 跨盘检测、冲突不覆盖 |
| `services/seeding.py` | 保种时长/分享率/磁盘水位策略 | 删除前二次校验 |
| `services/scheduler.py` | 定时 tick、任务锁、失败退避 | 单实例锁，避免重入 |
| `services/notifier.py` | 企业微信 / Server酱 / Bark / SMTP | 可关，失败不影响主流程 |
| `clients/douban.py` | 豆瓣公开榜单（剧集/电影/综艺，支持翻页、年份与类别筛选）；剧集总集数兜底（`episodes_count`） | 无需账号，失败降级，不阻塞 |

## 7. 主链路流程

### 7.1 新建订阅（两条入口：MT 搜索结果 / 豆瓣榜单）

```
用户在 Web UI 搜索关键词
  → 展示 MT 结果（名称/大小/免费/做种数/豆瓣ID/评分）
  → 点"订阅此剧/此片"
  → 自动带出：标题、年份、类型、豆瓣ID、季（可改）
  → 选择质量偏好与规则
  → 保存，进入调度
```

或者：

```
用户打开「豆瓣榜单」
  → 选择剧集/电影/综艺与排序（近期热门 / 最新上线 / 高分优先）
  → 可选年份/类别筛选；每页可选 20/50/100 条
  → 显示共约多少条与当前页/总页数，可用上一页/下一页或输入页码跳转
  → 点某个条目的"订阅"
  → 预填标题、年份、豆瓣ID（剧集/综艺再预填第 1 季）
  → 可改后保存，进入调度
```

三种榜单统一使用豆瓣公开推荐接口（综艺固定带 `tags=综艺`），筛选条件也拼进
`tags`；接口返回总条数（约 500 封顶）与每条年份。单次最多返回 50 条，
每页 100 条时由客户端分两次请求并按豆瓣 ID 去重合并。

MT 路径的订阅数据来自 MT 自身；豆瓣榜单走公开页面接口，不需要账号或 Cookie，
只用于**浏览与预填**，不参与匹配与刮削，因此断外网时只是榜单不可用。

### 7.2 定时追剧（核心循环）

```
每 5 分钟 tick
  └─ 选出到期订阅（last_checked_at + interval ≤ now 且 status=active）
      ├─ 拼关键词：中文名/别名 + 季集提示（如 "剧名 第2季"）
      ├─ 限速器等待 → POST /api/torrent/search（pageSize=100，一次拿够，不翻页）
      ├─ 硬过滤 → 打分排序 → 取 Top1（可配 TopN）
      │    排序：有明确集数范围时"仍缺集数"优先，再看评分/免费/做种/发布时间；
      │          无范围时按评分/免费/做种/发布时间
      ├─ 去重：mt_id 已处理 / 该集已有任务 / 标题+体积重复（TV 还需集数覆盖相同）
      ├─ 订阅未开启自动抓取 → 写入候选池，结束本轮（等人工确认；
      │    候选页默认只展示每个订阅的最优一条，可展开全部）
      ├─ 免费与预算检查（是否免费、是否超当日流量、分享率是否安全）
      ├─ POST /api/torrent/genDlToken → 得到临时下载 URL
      ├─ GET 下载 URL 拿 .torrent（**不带 x-api-key**）
      ├─ bencode 解析 → 文件列表 → 集数映射
      ├─ 再次校验集数（防止名不副实）
      ├─ qB torrents/add（上传 .torrent 二进制 + savepath + category + tag）
      └─ 落库、更新订阅进度、通知
```

### 7.3 下载与整理

```
每 60 秒轮询 qB
  └─ state=downloading 的任务
      ├─ 进度、速率写库（仪表盘展示）
      └─ 完成（progress=1 且 state=uploading/stalledUP）
          ├─ 扫描种子内容，选出正片视频文件（排除 sample/预告/花絮）
          ├─ 解析文件名 → 季集（文件级优先，其次种子级）
          ├─ 目标路径不存在 → 硬链接；已存在同大小 → 跳过
          ├─ 硬链接字幕（同名 .srt/.ass/.ass 等）
          ├─ 生成 NFO（可关）
          └─ 标记 organized，通知
```

### 7.4 保种与清理

```
每小时
  ├─ 统计各任务已做种时长、分享率、体积
  ├─ 满足 min_seed_hours 且（ratio ≥ 阈值 或 做种 ≥ 最长时限）→ 候选删除
  ├─ 磁盘水位超阈值 → 按"最久未使用"优先清理候选
  └─ 删除前确认：已 organized、非当前追新任务
```

> MT 社区经验：**分享率低于 0.3 会被封号、低于 0.6 警告**；且站点不标记 H&R，主要靠分享率约束。因此默认策略是"多保种、少删种"，删除条件宁严勿松。具体以站点当前规则为准。

## 8. MT API 适配（已核实）

### 8.1 认证

- 站点控制台 →「实验室 → 存取令牌」自助获取 **API Access Token**。
- 所有请求带请求头：`x-api-key: <TOKEN>`。
- **不再使用 Cookie**；站点明确说明第三方工具若仍以 Cookie 访问接口，可能被停用账号。
- 无 HMAC 签名、无时间戳校验、无会话过期 —— 这解决了痛点 1。

### 8.2 基础信息

| 项 | 值 |
|---|---|
| Base URL | `https://api.m-team.cc/api` |
| 请求头 | `x-api-key`、`Accept: application/json`、浏览器风格 `User-Agent` |
| 响应包 | `{"code":"0","message":"SUCCESS","data":...}`（`code=0` 或 message=SUCCESS 视为成功） |

### 8.3 用到的端点

| 端点 | 方法 | 参数 | 用途 |
|---|---|---|---|
| `/torrent/search` | POST JSON | `keyword`、`mode`、`pageNumber`、`pageSize`、`visible`、`categories`、`discount`、`videoCodecs`、`audioCodecs` | 搜种 |
| `/torrent/genDlToken` | POST form | `id` | 换临时下载 URL |
| （下载 URL） | GET | — | 拉 .torrent，**不带 api key** |
| `/member/profile` | GET/POST | — | 取分享率/上传/下载/魔力，做护栏与仪表盘 |

> `/torrent/detail` 存在但**默认不调用**：搜索结果已含打分所需字段，文件列表从 .torrent 里解析，调用 detail 只会浪费配额。

### 8.4 搜索结果关键字段

`id`、`name`、`smallDescr`、`category`、`size`、`numfiles`、`createdDate`、`labelsNew`、
`imdb`、`imdbRating`、`douban`、`doubanRating`、
`status.{seeders, leechers, timesCompleted, discount, discountEndTime, visible, banned}`

**douban / imdb 字段是本设计最强的防误抓手段**：订阅存 `douban_id` 后，可直接与种子字段比对。

### 8.5 速率限制（站方建议值，按最保守执行）

| 行为 | 站方建议 | 本项目默认预算 |
|---|---|---|
| `/torrent/search` | 1000 次 / 24h | ≤ 400 次 / 24h；全局最小间隔默认 0（可配，建议 20s） |
| `/torrent/detail` | 100 次 / 小时 | 不调用 |
| 下载种子 | 100 个 / 小时、1000 个 / 天 | ≤ 60 个 / 24h |

预算按"滑动窗口计数"存 SQLite，重启不清零；超预算则本轮跳过并延后订阅。
另按订阅设定间隔（连载默认 30 分钟、完结/电影默认 12 小时），避免无效高频搜索。

### 8.6 错误与退避

| 情况 | 处理 |
|---|---|
| HTTP 429 / 403 / 1010（Cloudflare） | 指数退避；连续 3 次 → 全局冷却 30 分钟 + 通知 |
| `code != 0`（密钥无效、额度不足等） | 暂停所有抓取 + 高优通知，等待人工处理 |
| 下载 URL 过期 / 拉取失败 | 重新 genDlToken，最多 3 次 |
| qB 添加失败（重复任务等） | 视为已存在，落库为 discovered，不重试 |

## 9. 选种与匹配

### 9.1 硬过滤（任一不满足直接淘汰）

1. `visible=1`、`banned=false`、有做种者。
2. 类型匹配：**优先用集数语义**（剧集必须能解析出集数或合集标记，电影不得带集数标记）；分类 ID 仅作可选过滤，配置后才生效（分类值待实测校准）。
3. **ID 校验**：订阅有 `douban_id`/`imdb_id` 时，种子带 ID 且不一致 → 淘汰；种子无 ID → 降级由标题判定。
4. **标题相似度**（无 ID 时）：归一化（去标点/组名/简繁统一）后与订阅名/别名比对 ≥ 0.75。
5. 年份：订阅有年份且种子名含年份时，偏差 > 1 → 淘汰。
6. 尺寸：在 `[min_size_gb, max_size_gb]` 内；默认排除 BDMV/原盘/CAM/枪版。
7. 分辨率/编码：命中订阅偏好集合。
8. 集数：与"待补集数"有交集；覆盖集数 ≥ `season_pack_min_missing`（默认 3）的合集，缺失集数也需 ≥ 该阈值；小合集（如 E07-E08，两集都缺）直接接受，作为多种子补集的一部分。
9. 去重：`mt_id` 已抓过、该集已有任务、标题+体积重复 → 淘汰。
10. 预算：非免费种需订阅显式允许 `allow_non_free`，且未超当日流量预算。

### 9.2 评分（用于 TopN 排序）

| 维度 | 分值 | 说明 |
|---|---|---|
| 分辨率命中优先级 | 30 | 4K > 1080p 按订阅顺序 |
| 中字/字幕标记 | 20 | 标题含 中字/简中/繁中/CHS/CHT |
| 免费 / 2XFREE | 15 | `discount` 字段 |
| 做种数 | 15 | `log10(seeders)*5`，封顶 |
| 体积接近理想值 | 10 | 与 `prefer_size_gb` 的偏差 |
| 发布时间 | 5 | 越新越高 |
| 作者/组偏好 | 5 | 可选白名单 |

阈值：总分 < 50 → 不自动抓，进"待确认"列表。

### 9.3 集数解析（`release_name.py`）

| 样式 | 规则 |
|---|---|
| `S01E05` / `S01E05E06` | 季 + 集（含连集区间） |
| `EP05` / `E05` / `第05集` / `第5话` | 集（季取自订阅） |
| `01-06` / `05~06` | 区间 |
| `全12集` / `Complete` / `Season 2` | 合集标记 |
| `第2季` / `Season 2` | 季 |

- 支持 `episode_offset`：动漫"第二季第 1 集 = 绝对第 13 集"这类错位，由订阅手工填写偏移。
- 文件级解析优先于种子级；文件解析失败时，单文件种子按种子集数推断，多文件合集按文件名排序兜底，仍失败则**不整理**并告警（不猜）。

### 9.4 幂等与去重键

- 主键：`mt_id`（唯一）。
- 业务唯一键：`(subscription_id, season, episode)`。
- 附加指纹：`normalize(title) + size_bytes`，防止同内容重复发布。

## 10. 媒体库整理

### 10.1 命名模板（可配置）

```
电影: {library}/Movies/{title} ({year})/{title} ({year}) - {resolution}.{ext}
剧集: {library}/TV/{title} ({year})/Season {season:02d}/{title} - S{season:02d}E{episode:02d}.{ext}
```

- `{category}` 取订阅的“媒体库分类”（动漫、纪录片等，可自由填写），留空时电影为
  “电影”、剧集为“电视剧”；默认模板不含该占位符。
- `{title}` 优先取订阅中文名，缺失时用种子名清洗结果。
- 多集文件：`S01E01-E03` 形式。
- 命名只影响硬链接目标，**不改下载目录文件名**。

### 10.2 硬链接与跨盘

- 默认 `os.link`；`EXDEV` 时按配置降级为 `copy`（默认）或 `symlink`，并在 UI 明示。
- 启动时自检：`DOWNLOAD_DIR` 与 `LIBRARY_DIR` 是否同一文件系统，结果展示在仪表盘。
- 不做移动、不做重命名、不做删除源文件。

### 10.3 冲突处理

- 目标已存在且大小相同 → 跳过（幂等）。
- 目标已存在但不同 → **不覆盖**，生成 `xxx (2).mkv` 并告警，交由人工处理。

### 10.4 NFO（兜底，默认关）

- **默认不生成**：极空间「极影视」自带刮削，正常无需 NFO。
- 仅当某部片在极影视中识别错误/无法识别时，可对该订阅单独打开"生成 NFO"，产出 `tvshow.nfo` / `season.nfo` / `episode.nfo` / `movie.nfo`，含 title、year、season、episode、`<uniqueid type="douban|imdb">`。
- 极影视是否优先读取本地 NFO 需在 M1 实测；若其忽略本地 NFO，则该兜底降级为"手工修正元数据"，不阻塞主链路。
- 不生成图片。

## 11. 元数据策略（不依赖 TMDB）

优先级由高到低，逐级降级，任何一级失败都不阻塞主流程：

1. **订阅手工字段**（从 MT 一键创建时自动带出）。
2. **MT 种子字段**：`name`、`smallDescr`、`douban`、`imdb`、`doubanRating`、`category`。
3. **豆瓣（可选，国内可达）**：用 `douban_id` 取正式译名/年份/海报；做缓存与频率限制，失败即跳过。
4. **纯离线**：仅靠种子名清洗 + 用户填写的标题年份，功能不受影响。

媒体服务器侧：**由极空间「极影视」自行刮削**，本项目不向它提供元数据，也不占用本项目的网络依赖；我们只负责把文件放进它扫描的目录、并保证命名正确。因此本项目**自身不访问 TMDB 等海外服务**；极影视的识别规则需在 M1 用真实文件校准（见 §19）。

## 12. 数据模型（SQLite）

> 本节为概念模型；**DDL、索引、迁移与清理策略以 [详细设计.md](详细设计.md) §4 为准**（已补充 `account_snapshot`、`job_run` 等表）。

```sql
CREATE TABLE subscription (
  id              INTEGER PRIMARY KEY,
  kind            TEXT NOT NULL CHECK (kind IN ('movie','tv')),
  title           TEXT NOT NULL,
  aliases         TEXT,              -- JSON array
  year            INTEGER,
  douban_id       TEXT,
  imdb_id         TEXT,
  season          INTEGER DEFAULT 1,
  episode_offset  INTEGER DEFAULT 0, -- 绝对集数偏移
  quality         TEXT,              -- JSON，见下
  rules           TEXT,              -- JSON，见下
  interval_min    INTEGER DEFAULT 30,
  status          TEXT DEFAULT 'active' CHECK (status IN ('active','paused','done')),
  last_checked_at TEXT,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);

CREATE TABLE torrent (
  id             INTEGER PRIMARY KEY,
  mt_id          TEXT NOT NULL UNIQUE,
  subscription_id INTEGER REFERENCES subscription(id),
  title          TEXT NOT NULL,
  size_bytes     INTEGER,
  discount       TEXT,
  seeders        INTEGER,
  category       TEXT,
  episode_start  INTEGER,
  episode_end    INTEGER,
  is_batch       INTEGER DEFAULT 0,
  score          REAL,
  score_detail   TEXT,              -- JSON，记录每个维度得分/淘汰原因
  state          TEXT DEFAULT 'new',-- new|grabbed|downloading|completed|organized|ignored|failed
  qb_hash        TEXT,
  save_path      TEXT,
  seed_started_at TEXT,
  error          TEXT,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL
);

CREATE TABLE episode_state (
  subscription_id INTEGER NOT NULL,
  season          INTEGER NOT NULL,
  episode         INTEGER NOT NULL,
  torrent_id      INTEGER,
  state           TEXT NOT NULL,     -- grabbed|downloading|completed|organized
  updated_at      TEXT NOT NULL,

);

CREATE TABLE api_budget (            -- 滑动窗口调用计数
  endpoint   TEXT NOT NULL,
  called_at  TEXT NOT NULL
);

CREATE TABLE event_log (
  id         INTEGER PRIMARY KEY,
  level      TEXT,
  source     TEXT,
  message    TEXT,
  payload    TEXT,                  -- JSON

CREATE TABLE setting (               -- 非敏感可调参数

);
```

## 15. 部署

```yaml
services:
  mtbox:
    image: mtbox:latest          # 建议本机 build 后导入，避免直连 Docker Hub
    env_file: .env
    volumes:
      - <配置目录>:/config        # SQLite + 日志
      - <下载目录>:/downloads     # 必须与 qBittorrent 映射到同一路径
      - <极影视扫描目录>:/media
    ports: ["18080:8080"]
    restart: unless-stopped
    environment:
      - TZ=Asia/Shanghai
      - PORT=8080
```

关键点：

1. **路径映射必须与 qBittorrent 容器一致**（都用 `/downloads`），否则拿到的 `save_path` 在本容器里不存在。
2. 下载目录与极影视扫描目录**尽量在同一存储池**，硬链接才生效；跨池自动降级为 copy 并在 UI 提示。
3. 极空间 Docker 的卷路径以创建容器时实际可选路径为准；启动时把解析后的真实路径打印到日志与仪表盘，便于核对。
4. 若固件不支持 Compose，提供等价的 `docker run` 命令；两种方式都写进 README。
5. 极空间拉取 Docker Hub 可能不稳定：**在开发机 build → `docker save` → 极空间 `docker load`**，或配置可用镜像加速。
6. 仅监听局域网；如需外网访问，自行加反向代理 + HTTPS，本项目不内置。
7. 首次启动默认 `DRY_RUN=true` 且自动化关闭：只搜索、只进候选池，不推送 qB。

环境变量（敏感项默认放这里；MT API Key 与 qB 密码可在设置页覆盖并保存到本地 SQLite，页面/日志不回显）：

```
MT_API_KEY=...
MT_API_BASE=https://api.m-team.cc/api
MT_USER_AGENT=Mozilla/5.0 ...
QB_URL=http://qbittorrent:8080
QB_USERNAME=...
QB_PASSWORD=...
DOWNLOAD_DIR=/downloads
LIBRARY_DIR=/media

```

## 16. 安全与站点合规

1. **API Key 管理**：默认存 `.env`（权限 600），也可在设置页保存到本地 SQLite；UI 只显示配置状态；日志过滤；绝不拼接到下载 URL；绝不写入仓库。
2. **只调允许的端点**：不使用 `/login`、`/admin/**`；不使用 Cookie。这既是站点要求，也是防封号的底线。
3. **分享率护栏**：定时读 `/member/profile`；`ratio < 0.8` 暂停非免费抓取，`ratio < 0.6` 全暂停并高优通知；同时限制每日下载流量预算。
4. **网页登录提醒**（**计划中，未实现**）：站点要求定期网页登录（社区经验为 40 天，封存可延长），脚本无法代替。计划做"上次手动确认登录"记录，临近到期前提醒。
5. **管理端认证**：单用户密码 + HttpOnly/SameSite Session Cookie；不做注册、不做多用户；默认仅内网。
6. **文件安全**：所有路径做越界校验（目标必须位于 `LIBRARY_DIR` 内）；解析 .torrent 时限制大小与文件数；不执行任何来自种子内容的代码。
7. **依赖最小化**：不用 CDN、不引重型框架，减少供应链面。

## 17. 实施阶段

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| **M0 骨架** | 配置、DB、日志、MT client、qB client、Docker、`/health`、dry-run | 容器起来；能搜索并展示候选；不触发下载 |
| **M1 手动闭环** | 搜索 → 手动选种 → 取种 → 推 qB → 完成后硬链接整理 | 一部电影、一集剧能从 MT 到极影视扫描目录并被正确识别 |
| **M2 订阅与候选** | 订阅 CRUD、调度、匹配评分、去重、集数进度、候选审核与一键下载 | 连载剧持续追新；同一集不重复；候选理由可解释 |
| **M3 运营与放开** | 分享率护栏、预算、保种清理、磁盘水位、通知、仪表盘；按订阅开关自动抓取 | 连续运行 24h 无风控/无重复/告警可达 |
| **M4 打磨**（计划中，未实现） | NFO 兜底、可选豆瓣元数据（非榜单）、合集策略、多季与偏移、定时备份 | 极影视识别异常时有兜底手段 |

豆瓣榜单浏览（发现与预填）与"每订阅自动选最优候选"已分别在 M2/M3 阶段落地；
M4 的"可选豆瓣"仅指用 `douban_id` 补元数据，两者互不依赖。

建议节奏：M0+M1 先跑通真实链路（这一步能暴露 90% 的路径/命名/权限问题），再谈自动化。

## 18. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 误抓（同名/改年份/李鬼） | 浪费流量、污染媒体库 | 豆瓣/IMDb ID 强校验；无 ID 提高标题门槛；低分进人工确认；dry-run 先观察 |
| API 限速/风控/Cloudflare 1010 | 搜索失败、账号受限 | 全局预算 + 最小间隔 + 浏览器 UA + 指数退避 + 冷却 |
| 分享率跌破阈值 | 账号被警告/封禁 | 免费优先、下载预算、护栏自动刹车 |
| 站点定期网页登录要求 | 账号失效 | 无法自动化；到期提醒尚未实现（见 [ROADMAP](../ROADMAP.md)） |
| 硬链接跨盘失败 | 整理失败或占双份空间 | 启动自检；可配 copy/symlink；UI 明示 |
| qB 路径与本容器不一致 | 找不到文件、整理失败 | 强制文档化"两容器同一路径映射"；启动校验 |
| 种子名不规范/无集数 | 整理错误或遗漏 | 文件级解析 + 多级兜底；不猜则告警 |
| 合集/季包重复下载已有集 | 重复占空间 | 缺失集数阈值；下载后按文件级去重整理 |
| 磁盘不足 | 下载中断 | 水位阈值告警 + 暂停抓取 + LRU 清理候选 |
| API 字段/分类 ID 变更 | 搜索不到或类型错配 | 分类 ID 配置化；字段缺失降级；版本化适配层 |
