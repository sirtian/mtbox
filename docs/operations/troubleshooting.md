# 故障排查

先看三处信息：

1. 仪表盘「启动自检」；
2. 「日志」页（按级别/模块过滤）；
3. `DATA_DIR/logs/mtbox.log`，或 `docker compose logs -f mtbox`。

## 启动失败

应用在启动时执行本地自检；目录、模板、路径映射等错误会直接中止启动，
凭据缺失只记警告（可登录后在设置页补）。

| 现象 | 原因 | 处理 |
|---|---|---|
| `PATH_MAP_JSON 不是合法 JSON` / `条目非法` | JSON 写错、不是数组，或路径不是绝对路径 | 使用 `[["/downloads","/vol1/downloads"]]` 这种形式；两侧都必须是绝对路径。 |
| `路径 ... 不在 PATH_MAP_JSON 中` | qB 报告的前缀没有映射 | 补充 qB 实际报告的前缀；最长前缀优先。 |
| `模板 ... 缺少 {title}` / 占位符非法 | 设置页模板写错 | 恢复默认模板，或只使用[配置参考](../configuration.md#2-运行时设置)列出的占位符。 |
| 启动即退出、日志显示目录不可写 | `/config`、`/media` 权限不足 | 修正挂载目录属主/权限；见 [Docker 部署](../deployment/docker.md#4-目录与权限)。 |
| 容器 unhealthy | 启动自检失败或端口不对 | 看 `docker logs`；确认 `PORT` 与健康检查/映射端口一致。 |

## qBittorrent

| 现象 | 排查 |
|---|---|
| 自检 `qBittorrent: 不可用: ...` | 在容器内访问 `QB_URL`：NAS 上不要写 `127.0.0.1`，应写宿主机局域网 IP + 映射端口；确认 qB Web UI 允许该网段访问。 |
| 登录失败 | 检查 `QB_USERNAME`；密码可能被设置页保存的旧值覆盖——在设置页清除 qB 密码覆盖后回退到 `.env`。 |
| 添加任务成功但文件找不到 | qB 与 mtbox 的 `/downloads` 挂载不一致，或 `PATH_MAP_JSON` 写错；整理日志会显示原始路径与映射结果。 |
| 整理提示文件不存在 | 确认任务已完成、qB 的 `content_path` 对 mtbox 可见；若 qB 使用「创建子文件夹」，程序会按 `content_path` 与同级唯一同名文件兜底。 |
| 删除任务后 qB 里还在 | 删除调用失败时任务会保留并记录错误；看日志后重试。`DRY_RUN=true` 不会真正删除。 |

## M-Team

| 现象 | 排查 |
|---|---|
| `M-Team 认证失败` / 401 | Token 错误、过期或复制不完整；只使用控制台「存取令牌」，不要使用 Cookie。 |
| `M-Team 限流或 Cloudflare 拦截` | 降低搜索预算，在设置页把「搜索最小间隔」调高（例如 20 秒），确认 `TRUST_ENV_PROXY=false`；UA 保持默认浏览器 UA。 |
| `429` / 预算耗尽 | 24h 预算用完；等窗口滚动，或在设置页调整搜索预算、降低自动检查频率。 |
| 搜索 0 条 | 换中文名/原名/别名；检查 `mode_map`；电影与剧集的搜索 `mode` 可能不同。 |
| 取种失败 | 消耗取种预算但未拿到地址，通常是令牌过期或站点临时错误；稍后重试。 |

## 下载与整理

| 现象 | 原因/处理 |
|---|---|
| 一直「待整理」 | `ORGANIZE_DELAY_SEC` 未到，或定时任务被关闭（`SCHEDULER_ENABLED=false`）；可手动点「整理待处理」。 |
| 「整理失败」 | 看错误详情：路径映射、文件缺失、权限、跨盘。修复后点「重试」。 |
| 媒体库出现两份 | 下载目录与媒体库跨文件系统，硬链接退化为复制；把两者放到同一存储池。 |
| 极影视识别不到 | 检查命名模板、季/集号、媒体库分类；必要时调整模板后对任务「重新整理」。 |
| 分集重复下载 | 查看任务/分集状态；「删除任务」会释放未整理分集，已整理分集不会重复抓取。 |

## 登录

- 连续 5 次密码错误会锁定 5 分钟；等待或重启进程即可解除（限速状态在内存中）。
- 修改 `ADMIN_PASSWORD` 后必须重启/重建容器；`docker restart` 不会重新读取 `.env`，
  用 `docker compose up -d --force-recreate`。
- 所有会话突然失效：检查 `secret.key` 是否丢失或被替换；它必须持久化在 `DATA_DIR`。

## 豆瓣榜单

- 榜单只读公开页面；NAS 无法访问豆瓣时，榜单页显示错误或旧缓存，**不影响**订阅检查与下载。
- 需要代理时设置 `TRUST_ENV_PROXY=true`；但 M-Team 直连正常时不要随意开启。
- 豆瓣改版可能导致解析失败，等待更新；可用搜索页手动建订阅绕过。

## 安全与预期行为

- `/docs`、`/redoc`、`/openapi.json` 返回 404 是**预期行为**：项目没有公开 JSON API，
  只提供网页与 `/health`。
- `/health` 无需登录，会返回数据库/调度器/qB/预算状态；不要把它暴露到公网。
- 设置页不会回显 API Key 与密码，只显示「已配置/未配置」。
- `DRY_RUN=true` 时不会取种、不会删除 qB 任务，候选与日志仍会生成。

## 收集诊断信息

提交 issue 前，请提供（**不要包含 API Key、密码、Cookie、完整 `.env`**）：

- 版本：`mtbox --version`；
- 部署方式（Docker/本地、架构）；
- 自检结果与相关日志片段（先自行掩码敏感值）；
- `PATH_MAP_JSON` 的结构（可替换真实目录）；
- 复现步骤与预期行为。

安全问题请按 [SECURITY.md](../../SECURITY.md) 私下报告。
